# 寰引智能官网对外代运营 API 产品化实施 PRD

> 版本：v0.2，2026-10-09（中国标准时间）。
> 目标与范围：按用户明确纠偏锁定；实现及生产状态仍须以云端证据验收。
> 本文件是本轮唯一执行规格。v0.1 消费方接入方向被本版替代，历史内容可在 Git 中追溯。
> 本机规划文件；云端项目正式 docs 尚待同步。本文件不证明生产能力。

## 1. 业务目标

我们是官网 API 提供方。第三方代运营系统调用我们提供的接口，读取授权内容，新增或修改草稿，提交审核，在获准条件下发布，查询结果并恢复错误变更。网站公开页面、SEO/GEO 内容与发布快照保持一致。

交付标准是任意合规服务端客户端可依据契约接入，不依赖某一家第三方、不要求先获取第三方内部资料。第三方真实联调作为后续独立验收。

本轮不建设第三方消费方、不修改 AIGEO-OS 项目、不采集第三方信息、不建设多租户 SaaS 或另一个 CMS；不承诺搜索收录、AI 引用、排名和增长。

## 3. 用户与典型流程

- 官网管理员：创建或撤销授权、分配范围和时效、审核受保护修改、查审计、处理失败。
- 第三方服务端：获得正式授权后获取 Token，发现可用资源，读取内容与 ETag，创建/修改草稿，提交审核或执行已获准发布，读取回执。
- 官网访问者：只看到已发布版本；草稿及测试内容不改变公开内容。

标准流程：管理员授权 → 第三方获取 Token → 发现资源及 schema → 写草稿 → 审核/发布 → 查回执与公开结果。一个第三方是否使用某家模型、运营平台或内部任务系统，与官网 API 无关。

## 4. 提供方需求与验收

| 编号 | 必须交付的结果 | 验收证据 |
|---|---|---|
| PROVIDER-01 | 明确机器身份授权、时效、scope、资源/记录范围、撤销规则；默认按最小权限接入 | Token 正常/过期/越权/撤销的隔离 HTTP 验收；管理员授权说明 |
| PROVIDER-02 | 对外版本化资源与字段契约准确，覆盖既有 10 内容域和媒体等独立端点 | 生成 OpenAPI 与实际路由/schema 对比；未知字段和不可变字段的负向测试 |
| PROVIDER-03 | 内容治理行为可预测：草稿与公开版隔离、审核发布、下线、归档恢复、回滚 | 生命周期 HTTP 验收；草稿不改变公开版；回滚恢复草稿后再发布 |
| PROVIDER-04 | 并发与重试可靠：If-Match/ETag、幂等键、操作回执、稳定错误语义 | 过期 ETag 412、幂等冲突 409、相同请求不重复、失败可查回执 |
| PROVIDER-05 | 第三方可直接使用的 OpenAPI、服务端 SDK 和接入指南 | 最小调用示例从鉴权到查询回执可在隔离测试运行；错误/重试行为与契约一致 |
| PROVIDER-06 | 提供受控自测方式，无需真实第三方即可证明提供方可用 | 隔离数据库、内容与凭据运行；测试不写生产内容；测试授权可撤销 |
| PROVIDER-07 | 官网管理员能查授权和审计，区分 API 接受、发布和公开页面生效 | 管理端与回执/readiness 检查；日志和文档无秘密 |
| PROVIDER-08 | 发布、回滚、兼容策略与交付状态可追溯 | 类型检查、单测、构建、隔离验收、备份/回滚点、串行生产验收和文档收口 |

资源范围以云端 `GET /resources`、路由和 schema 为准。记录中的 10 类资源为 blog-posts、cases、industries、company、customers、capabilities、stats、contacts、settings、pages；media、analytics、submissions、operations 等独立端点按实际授权说明，不能当作默认全部开放。

## 5. 关键业务约束

- 第三方不具备管理员 approve 权限。普通内容自动发布要求 content:publish、autoPublish 及确定性证据门禁同时满足；不得凭 scope 绕过保护字段治理。
- 营销数字、客户和品牌事实、联系方式、canonical、robots/noindex、法律信息按既有保护策略执行。开发测试不改正式客户内容或营销统计。
- 回滚恢复 draft，必须再次发布才改变公开版；不存在未经确认的 rejected 生命周期。
- slug/pageKey 按既有不可变契约；pages 是固定模板白名单，不是任意页面生成接口。
- 内容 schema 拒绝未知字段；不把代运营任务、问句、第三方运行记录塞入内容模型。
- SDK 和测试示例不嵌入凭据；文档使用占位符。凭据发放是实际合作接入步骤，不是本轮 API 建设的验收前置。
- sitemap、llms、页面元信息是否及时反映发布版本需实测；外部搜索提交及 public observation 分别验收，不能由 API 成功推断。

## 6. 实施契约与文件边界

在云端确认 HEAD、工作树和唯一写入任务后，复用合适的隔离 worktree。先建立逐项缺口清单，已有且验收通过的能力只补对外交付说明。

预计允许文件：`lib/operations/**`、`app/api/integrations/v1/**`、与实际缺口有关的管理端、`sdk/site-operations.mjs`、`scripts/generate-operations-openapi.mjs`、`scripts/operations-http-acceptance.mjs`、现有相关测试、`docs/api/**` 及受影响运维/发布说明。不修改无关页面布局、AIGEO 代码、生产内容数据。

每个切片留下“PROVIDER 编号 → 文件 → 命令/结果”追踪。发现需要新增业务权限、改变数据语义或扩展产品范围时，记录偏差候选；实现细节由执行代理判断。

步骤：云端基线核验 → 契约/SDK/文档缺口修复 → 隔离验收与评审 → 备份和标准发布 → 生产验收 → 提供方交付包与经验沉淀。发布与生产验收串行。

验收命令使用当前云端 package/scripts 中的真实命令，不能以历史 108/28 数字代替本轮运行。测试证据保留环境、时间、SHA、结果和失败原因。

## 7. 交付包

1. OpenAPI 与版本/兼容规则，包括字段、权限、状态转换、错误码及分页等实际支持行为。
2. 服务端 SDK 与最小调用示例：Token、资源读取、草稿创建/更新、提交审核、回执查询；只有契约允许时演示发布。
3. 管理员授权操作与撤销说明，第三方接入说明和受保护内容规则。
4. 隔离验收工具与脱敏报告、发布/回滚指引、能力限制与待验证项。

不得把 SDK 示例写成“已接通某第三方”，不得因缺少某第三方联系人推迟提供方交付。
