# 寰引智能官网 API 第三方对接文档

> 文档版本：1.0｜日期：2026-10-09
> 适用接口：API v1｜适用交付版本：v1.8.1
> 接口提供方：寰引智能官网｜接入方：获授权的第三方代运营系统

## 1. 对接目的

寰引智能官网提供标准 API，由第三方代运营系统在授权范围内读取、新增、修改与维护官网内容，包括博客、案例、行业方案、页面文案及 SEO/GEO 相关字段。

接入方在自己的服务端实现 API 调用和运营流程；官网负责接口、授权、内容审核与发布治理。接入无需提供第三方内部模型、算法或业务数据。

## 3. 接入地址与凭据

正式 API 基础地址：

```text
https://huanyinai.com/api/integrations/v1
```

以下信息在官网管理员创建正式授权后，单独安全交付：

| 信息 | 用途 |
|---|---|
| Client ID | 识别接入方 |
| Client Secret | 服务端获取 Access Token |
| 授权 scope | 确定读、写、发布或媒体等操作权限 |
| 资源/记录范围 | 限定可访问的内容域及具体记录 |
| 合作截止和 Secret/Token 时效 | 确定授权有效期 |
| 自动发布是否开启 | 明确普通内容是否可按治理条件自动发布 |

Client Secret 仅保存在接入方服务端的秘密管理设施，不放前端、代码仓库、工单、对接文档或调用日志。Token 到期后重新获取；授权禁用或撤销即时影响已发 Token。

## 4. 双方职责与首次授权

| 官网提供方 | 第三方接入方 |
|---|---|
| 提供接口契约、SDK、示例与指南 | 根据资料实现自己的服务端客户端 |
| 确认运营范围，创建最小权限授权 | 提供合作方名称、技术联系人、所需资源和操作范围 |
| 按约定安全交付、轮换或撤销凭据 | 妥善保存凭据，处理错误、限流、幂等和并发修改 |
| 审核受保护内容和处理发布/恢复异常 | 提供事实来源，不虚构客户、指标或审核结果 |
| 配合检查官网公开生效结果 | 保留脱敏 requestId/operationId，完成真实联调验收 |

建议首次联调仅授予所需资源的 `content:read`、`content:write`，先验证“读取 → 草稿 → 提交审核 → 回执”。发布权限及 autoPublish 在明确运营规则后另行授予；媒体与咨询线索权限按实际需求单独配置。

具体合作方信息用于实际授权登记，不是官网 API 产品建设的前置条件。接入前双方填写：

| 对接确认项 | 待确认内容 |

| 接入方名称及技术联系人 | 接入方填写 |
| 所需内容资源、操作与记录范围 | 双方确认 |
| 是否需要媒体或聚合数据 | 双方确认 |
| 是否需要发布权限或普通内容自动发布 | 双方确认 |
| 合作有效期及凭据交付方式 | 双方确认 |
| 首次测试内容、审核协作与验收时间 | 双方确认 |

## 5. 接入步骤

1. 接收本文档和技术资料，阅读指南并核对版本。
2. 双方确认运营范围；官网管理员创建授权并安全交付凭据。
3. 服务端调用 `POST /oauth/token` 获取 Token。使用 `application/x-www-form-urlencoded` 和 `grant_type=client_credentials`，HTTP Basic 或表单凭据二选一；编码要求见指南。
4. 发送 `Authorization: Bearer <token>`，调用 `GET /resources` 确认当前身份可用资源，再读取记录。
5. 在双方约定的测试范围创建或修改草稿，查询回执；修改需使用当前 ETag，写入建议固定幂等键。
6. 提交审核并配合官网管理员处理；只有具备相应授权、内容证据和治理条件时才发布。
7. 核对公开页面与发布版本，验收失败、越权、并发和撤销场景，完成真实第三方接入记录。

接入包中的 `example-draft.mjs` 会实际创建草稿，应在获得授权且双方约定测试内容后运行。正式地址不是任意写入测试沙盒；包内也不包含可供第三方直接登录的独立沙盒账号。

## 6. 可运营内容与权限边界

接口覆盖 10 类内容域：blog-posts、cases、industries、company、customers、capabilities、stats、contacts、settings、pages。具体可用范围由授权与 `GET /resources` 决定，不是默认全部开放。

- 新增、编辑先形成草稿，未发布前不会替换官网公开版本。
- 第三方可按授权提交审核，但不能调用管理员 approve 权限。
- 普通内容自动发布要求发布权限、autoPublish 授权及内容证据等治理条件同时满足。
- 品牌、真实客户、联系方式、营销统计、canonical/robots/法律等受保护内容，仍受官网管理员复核约束。
- 页面运营限于固定模板及已开放字段，不支持通过内容接口注入任意 HTML、脚本或生成任意页面布局。
- slug/pageKey 不能改变；回滚形成草稿，再次发布后才改变公开版本。
- 媒体、聚合数据、咨询线索属于独立能力；敏感线索不默认开放。服务器、数据库、管理员审计等不属于第三方内容 API 权限。

## 7. 实现要求与结果判断

| 要求 | 接入方处理方式 |
|---|---|
| 并发修改 | PATCH 携带 If-Match；412 表示 ETag 过期，重新读取并合并意图；428 表示缺失 |
| 幂等重试 | 内容建议采用 8–128 字符键；媒体写入必须采用 1–200 个不含空格的可打印 ASCII 字符；统一采用 8–128 字符可满足两者 |
| 写请求重试 | 同一意图沿用同一键、方法、路径、载荷和原 If-Match；请求发生变化时使用新意图和新键 |
| 回执 | 只有 committed 表示操作完成；pending 需查询；failed/needs_recovery 需检查并协作恢复 |
| 鉴权/限流 | 401 检查失效或撤销；403 检查权限/资源/治理；429 按 Retry-After 等待 |
| 错误定位 | 保存脱敏 requestId、operationId、error/code 和必要 details；不记录 Secret 或 Token |
| 文件上传 | 媒体使用 multipart/form-data；SDK request 为 JSON 方法，上传需原生 fetch/FormData |

SDK 会缓存 Token、合并并发鉴权、保留错误详情与失败回执。401 清除缓存，下一次显式调用重新鉴权；不会自动重放失败的写请求。

机器客户端建议明确声明集成 User-Agent。边缘层返回的 HTML/无 requestId 错误，与应用返回的 JSON 权限错误分别排查。具体字段、错误码和媒体限制见指南。

**请求被接受、操作 committed、公开内容已发布和搜索/AI 可见性，是不同验收结果。** 草稿操作 committed 不能视为公开发布，公开发布也不能视为搜索收录、AI 引用或排名提升。

## 8. 第三方真实联调验收

| 验收项 | 合格要求 |
|---|---|
| 鉴权 | 正常获取并使用 Token；过期/失效能正确处理 |
| 范围限制 | 仅可读取和修改授权资源/记录；越权被拒绝 |
| 草稿 | 创建/修改成功且未改变公开页面 |
| 并发与幂等 | ETag 冲突不覆盖他人修改；重试不重复创建或执行 |
| 审核发布 | 按授权完成流程；第三方不能绕过管理员审核边界 |
| 操作结果 | 正确处理 committed/pending/failed/needs_recovery，并保留回执 |
| 公开生效 | 有发布授权时，核对目标页面、公开版本及相关元信息 |
| 撤销 | 撤销测试授权后，原 Token 无法继续调用 |
| 日志 | 仅保留脱敏诊断信息，无凭据明文 |

提供方 v1.8.1 已完成提供方侧验收；具体第三方系统仍需完成以上真实联调。是否已接通以双方实际调用及验收记录为准。

## 9. 对接问题反馈

反馈时提供接口版本、时间与时区、方法及脱敏路径、HTTP 状态、error/code、requestId/operationId、预期行为与实际行为。不要提供 Client Secret、Token、管理员密码或完整请求头；客户隐私和内容载荷按需脱敏。

发生错误内容或发布异常时，先保留回执并联系官网管理员确认恢复步骤，避免批量重复写入。API 路径为 v1；新增破坏性契约由提供方明确通知迁移，不以交付包文件名推断接口已变更。
